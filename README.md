# NFT Offer Bot (Telegram Business)

Telegram Business-бот, который создаёт предложения о покупке NFT-подарков в диалогах подключённого бизнес-аккаунта.

> **Важное ограничение Telegram API — текущий сценарий .off в бизнес-чате не заработает.** Bot API передаёт бизнес-боту обновления о сообщениях, полученных подключённым аккаунтом. Сообщение, которое владелец сам набирает и отправляет собеседнику, не является входящим business_message и не может надёжно использоваться как команда для бота. Поэтому текущий обработчик, который ожидает .off от владельца внутри бизнес-чата, не сможет сработать в описанном сценарии. До деплоя нужно изменить способ создания предложения: например, владелец отправляет команду в личный чат с ботом, указывая username/ID получателя, ранее обнаруженного ботом в бизнес-чате. См. [официальное описание business updates](https://core.telegram.org/bots/api#update) и [Connected Business Bots](https://core.telegram.org/api/bots/connected-business-bots).

## Что делает

1. Владелец бизнес-аккаунта подключает бота: **Настройки → Telegram Business → Чат-боты**.
2. В бизнес-чате с получателем владелец отправляет команду со ссылкой, суммой и валютой:
   ```
   .off https://t.me/nft/PlushPepe-1 1400 star
   .off https://t.me/nft/PlushPepe-1 10 gram
   ```
3. Бот проверяет ссылку, сумму и валюту и публикует предложение с кнопками **✅ Принять** и **❌ Отклонить**.
4. Получатель (собеседник) нажимает кнопку. Только он может ответить на предложение.
5. После принятия бот показывает инструкцию по передаче подарка. Дальше бот ничего не делает: передачу подтверждает пользователь сам в Telegram.

Бот не проводит оплату и не передаёт NFT. Сумма и валюта в сообщении — только обозначения предлагаемой цены. Автоматических конвертаций между валютами нет.

## Команда .off

Формат ровно из четырёх частей:

```
.off <ссылка на NFT> <сумма> <валюта>
```

| Валюта | Обозначения (регистр не важен) | Отображение |
|---|---|---|
| Telegram Stars | `star`, `stars` | `⭐ Telegram Stars` |
| TON | `gram`, `ton` | `TON` |

- **Ссылка** должна быть вида `https://t.me/nft/Название-Номер`.
- **Сумма** — положительное число (`1400`, `2.5`, `2,5`).
- Сумма и валюта всегда берутся из команды. Значений по умолчанию нет.

Примеры ответов бота:

- `.off https://t.me/nft/PlushPepe-1 1400 star` → `предлагает вам 1400 ⭐ Telegram Stars за этот подарок.`
- `.off https://t.me/nft/PlushPepe-1 10 gram` → `предлагает вам 10 TON за этот подарок.`

Ошибки ввода:

- Не хватает суммы или валюты, или лишние части → `❌ Неправильный формат команды.` с примерами.
- Сумма не число, ноль или отрицательная → `❌ Сумма некорректна…`
- Неизвестная валюта → `❌ Неизвестная валюта…` с перечнем допустимых.
- Ссылка не на NFT → `❌ Неверная ссылка на NFT…`

Команда `/start` в личном диалоге с ботом показывает инструкцию.

## Ограничения Telegram Bot API

- **Данные NFT по ссылке не запрашиваются.** Bot API не предоставляет метода «получить подарок по ссылке t.me/nft/…». Название и номер берутся только из самой ссылки (`PlushPepe-1` → `PlushPepe` и `1`). Бот не проверяет, что подарок существует и принадлежит собеседнику.
- **Стоимость передачи не проверяется.** `TRANSFER_FEE_TEXT` — справочная информация, а не актуальная цена Telegram.
- **Отправка от имени бизнес-аккаунта** возможна только если у бота есть право отвечать (`can_reply`). Это выдаёт владелец в настройках бота в Telegram Business.
- **Нажатия кнопок в бизнес-чатах** приходят как callback от собеседника. Поведение нужно проверить на реальном аккаунте.
- Бот не работает через личный аккаунт (userbot) и видит только подключённые бизнес-диалоги.

## Структура

```
nft-business-bot/
├── bot/
│   ├── business.py     # отправка и редактирование от имени бизнес-аккаунта, тексты
│   ├── config.py       # переменные окружения, валюты и валидация суммы
│   ├── database.py     # SQLite: подключения и предложения
│   ├── handlers.py     # /start, .off, business_connection, кнопки
│   ├── keyboards.py    # inline-кнопки
│   └── nft_parser.py   # разбор ссылки t.me/nft/Название-Номер
├── main.py             # запуск long polling
├── requirements.txt
├── render.yaml
├── .env.example
└── .gitignore
```

Статусы предложения: `pending` → `accepted` или `rejected`. Переход выполняется одним атомарным `UPDATE … WHERE status = 'pending'`, поэтому повторные нажатия не работают. В одном диалоге не может быть два активных предложения на одну ссылку.

Валюты хранятся в базе как `Stars` и `TON`. Старые записи с `GRAM` остаются как есть и продолжают читаться.

## Локальный запуск

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env             # заполните BOT_TOKEN
python main.py
```

## Развёртывание на Render

1. **New → Blueprint** (или Background Worker), подключите GitHub-репозиторий.
2. Render прочитает `render.yaml`: создастся worker и диск `bot-data` на `/var/data`. Постоянный диск требует платного плана, проверьте условия в документации Render.
3. Заполните переменные окружения.
4. **Deploy**. В логах должно быть `starting long polling`.

База хранится в `/var/data/bot.sqlite3` и сохраняется при перезапусках.

Если сервис уже был развёрнут со старой версией, переменные `DEFAULT_AMOUNT` и `DEFAULT_CURRENCY` можно удалить: новая версия их не читает.

## Переменные окружения для Render

| Переменная | Обязательна | Значение |
|---|---|---|
| `BOT_TOKEN` | да | токен от @BotFather. Не публикуйте его. |
| `ADMIN_ID` | нет | ваш числовой Telegram ID. Сюда приходят сообщения об ошибках. |
| `DATABASE_PATH` | да | `/var/data/bot.sqlite3` |
| `TRANSFER_FEE_TEXT` | нет | текст-напоминание о стоимости передачи |

## Проверка после деплоя

1. Подключите бота в Telegram Business и выдайте право отвечать.
2. В бизнес-чате отправьте `.off https://t.me/nft/Test-1 5 stars`, затем `.off https://t.me/nft/Test-1 5 TON`.
3. Проверьте текст предложения и валюту.
4. Нажмите «Принять» с аккаунта собеседника. Кнопки должны исчезнуть.
5. Повторное нажатие должно показать «Предложение уже обработано».

## Устранение неполадок

- **Бот молчит.** Проверьте, что подключение включено и у бота есть право отвечать. Смотрите логи Render.
- **«Не удалось отправить предложение».** Скорее всего, у бота нет прав в этом бизнес-подключении.
- **Кнопки не отвечают.** Проверьте логи и поведение callback на вашем аккаунте.
