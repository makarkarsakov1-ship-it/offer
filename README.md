# NFT Offer Bot — Telegram Business

Бот помогает владельцу Telegram Business отправлять предложения о покупке NFT-подарков собеседникам, которые уже писали бизнес-аккаунту.

## Как работает новый сценарий

Telegram Business Bot API не предоставляет боту надёжный поток исходящих сообщений, которые владелец сам набирает в бизнес-чате. Поэтому команда создания предложения отправляется владельцем **в личном чате с ботом**, а не в чате с покупателем.

1. Владелец подключает бота в **Настройки → Telegram Business → Чат-боты** и выдаёт доступ к нужным чатам и право отвечать.
2. Покупатель должен первым написать бизнес-аккаунту. Бот автоматически сохраняет его Telegram ID, username, чат и время последнего входящего сообщения.
3. Владелец открывает личный чат с ботом и отправляет команду:
   ```
   .off @username https://t.me/nft/PlushPepe-123 1400 star
   .off @username https://t.me/nft/PlushPepe-123 10 gram
   ```
   Вместо `@username` можно использовать числовой Telegram ID.
4. Бот находит собеседника среди сохранённых контактов и отправляет предложение **от имени подключённого Business-аккаунта** в существующий чат.
5. Получатель нажимает «Принять» или «Отклонить». После принятия бот показывает инструкцию; передачу подарка пользователь выполняет самостоятельно.

## Команды

- `/start` — инструкция.
- `/contacts` — список последних собеседников, обнаруженных в бизнес-чатах.
- `.off @username <NFT-ссылка> <сумма> <валюта>` — создать предложение.
- Также поддерживается `/off` вместо `.off`.

Валюты (регистр не важен):
- `star`, `stars` → Telegram Stars.
- `gram`, `ton` → TON.

Примеры:
```
.off @example https://t.me/nft/PlushPepe-123 1400 star
.off 123456789 https://t.me/nft/PlushPepe-123 10 gram
```

Сумма должна быть положительным числом. Значений по умолчанию и конвертации валют нет.

## Ограничения Telegram

- Получатель должен хотя бы раз написать подключённому Business-аккаунту, чтобы бот получил его chat ID. Bot API не позволяет боту произвольно открыть личный диалог с любым username.
- Ответ от имени Business-аккаунта доступен только при активном подключении и разрешении `can_reply`. Telegram ограничивает ответы в бизнес-диалогах временным окном после последнего входящего сообщения; в коде используется консервативная проверка около 24 часов, но окончательное решение принимает Telegram.
- Bot API не предоставляет метод получения названия/номера подарка по NFT-ссылке. Название и номер извлекаются из slug ссылки и не проверяются на существование или принадлежность.
- `TRANSFER_FEE_TEXT` — информационная подпись. Бот не получает актуальную стоимость передачи, не проводит оплату и не передаёт NFT.
- Нажатия кнопок и редактирование бизнес-сообщения нужно дополнительно проверить на реальном Telegram-аккаунте.

```bash

pip install -r requirements.txt
cp .env.example .env
python main.py
```

В Windows активируйте окружение командой `.venv\\Scripts\\activate`.

## GitHub и Render

1. Загрузите содержимое репозитория на GitHub.
2. В Render выберите **New → Blueprint** и подключите репозиторий. Файл `render.yaml` создаёт Background Worker и persistent disk с mount path `/var/data`.
3. Добавьте секретный `BOT_TOKEN` и свой `ADMIN_ID` (необязательно) в Environment.
4. Запустите деплой. В логах ожидается `starting long polling`.

Persistent disk в Render доступен на поддерживаемых платных планах; проверьте тариф перед созданием. База SQLite располагается по пути `/var/data/bot.sqlite3`.

## Переменные окружения

| Key | Значение |
|---|---|
| `BOT_TOKEN` | Обязательный токен от @BotFather |
| `ADMIN_ID` | Необязательный числовой Telegram ID для уведомлений об ошибках |
| `DATABASE_PATH` | `/var/data/bot.sqlite3` |
| `TRANSFER_FEE_TEXT` | Необязательное информационное сообщение о комиссии |

## Тестирование после деплоя

1. Владелец отправляет боту `/start`.
2. Подключает бота к Telegram Business и выдаёт доступ к нужным чатам и право отвечать.
3. Другой пользователь пишет бизнес-аккаунту.
4. Владелец открывает `/contacts` в личном чате с ботом и убеждается, что контакт появился.
5. Владелец отправляет `.off @username https://t.me/nft/PlushPepe-123 1400 star`.
6. Проверяет, что предложение пришло от Business-аккаунта.
7. Получатель нажимает «Принять» или «Отклонить». Проверить, что исходное сообщение отредактировалось и кнопки исчезли.

Если отправка не проходит, смотрите логи Render и проверьте Business Connection, право `can_reply` и время последнего входящего сообщения.
