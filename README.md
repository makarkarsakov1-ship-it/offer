# NFT Offer Bot — Telegram Inline Offers

Бот помогает владельцу Telegram Business отправлять предложения о покупке NFT-подарков собеседникам, которые уже писали бизнес-аккаунту.

## Как работает inline-сценарий

1. В BotFather включи Inline Mode командой `/setinline` и задай placeholder, например `NFT-ссылка сумма валюта`.
2. Открой личный чат с нужным человеком.
3. В поле сообщения введи:
   ```
   @ИМЯ_БОТА https://t.me/nft/PlushPepe-123 1400 star
   ```
   или `@ИМЯ_БОТА https://t.me/nft/PlushPepe-123 10 gram`.
4. Выбери результат «Предложение…» из списка. Telegram отправит его в текущий чат **от твоего аккаунта**, вместе с кнопками.
5. Получатель нажимает «Принять» или «Отклонить». Бот изменяет inline-сообщение и убирает кнопки.

Поддерживаются `star`, `stars`, `gram` и `ton`. Сумма Stars должна быть целой. NFT-ссылка разбирается по slug, но бот не проверяет существование подарка или владение им.

**Важно:** inline-сообщение отправляется от твоего личного аккаунта, не от Telegram Business. Бот не может отправлять такие предложения от имени пользователя автоматически — ты сам выбираешь результат в чате. Бот обслуживает кнопки и редактирует выбранное inline-сообщение. Первым ответившим на кнопки становится получатель предложения; владелец не может принять собственное предложение.

## Render Free: webhook

Проект настроен как бесплатный Render Web Service и получает обновления Telegram через webhook, а не через long polling.

1. Откройте существующий Blueprint **NFT Offer Bot** в Render. Он уже создан для репозитория `makarkarsakov1-ship-it/offer`.
2. Убедитесь, что в GitHub в `main` находится обновлённый `render.yaml`, затем запланируйте синхронизацию Blueprint.
3. Просмотрите план. Он должен создавать один Web Service с планом `free`, регионом Frankfurt, командой запуска `python main.py` и health check `/healthz`.
4. Примените план в Render. При первом применении Render может запросить значение `BOT_TOKEN`; добавьте токен в Environment сервиса, не публикуя его в GitHub или чате.
5. После запуска Render автоматически задаёт `RENDER_EXTERNAL_URL`. Приложение использует его для регистрации Telegram webhook. Дополнительный публичный URL вручную задавать не нужно.
6. В логах ожидается сообщение `webhook server listening` и успешная настройка webhook.

### Ограничения бесплатного тарифа

- Бесплатный Web Service засыпает после периода без входящего трафика. Первое сообщение после простоя может обрабатываться с задержкой из-за холодного запуска.
- Бесплатный тариф не поддерживает persistent disk. SQLite хранится в `/tmp/bot.sqlite3`; данные могут исчезнуть после перезапуска, пересборки или повторного деплоя.
- Поэтому список бизнес-контактов и история предложений не гарантированно сохраняются. После потери базы пользователям может понадобиться написать бизнес-аккаунту заново, чтобы бот снова увидел их.
- Telegram повторяет доставку webhook при временных ошибках, но нельзя гарантировать мгновенную доставку при пробуждении бесплатного сервиса.
- Этот вариант не требует добавления платёжных данных, пока Render допускает создание Free Web Service для аккаунта.

## Ограничения Telegram

- Получатель должен хотя бы раз написать подключённому Business-аккаунту, чтобы бот получил его chat ID. Bot API не позволяет боту произвольно открыть личный диалог с любым username.
- Ответ от имени Business-аккаунта доступен только при активном подключении и разрешении `can_reply`. Telegram ограничивает ответы временным окном после последнего входящего сообщения; в коде используется консервативная проверка около 24 часов, но окончательное решение принимает Telegram.
- Bot API не предоставляет метод получения названия/номера подарка по NFT-ссылке. Название и номер извлекаются из slug ссылки и не проверяются на существование или принадлежность.
- `TRANSFER_FEE_TEXT` — информационная подпись. Бот не получает актуальную стоимость передачи, не проводит оплату и не передаёт NFT.
- Нажатия кнопок и редактирование бизнес-сообщения нужно проверить на реальном Telegram-аккаунте после деплоя.

## Переменные окружения

| Key | Значение |
|---|---|
| `BOT_TOKEN` | Обязательный токен от @BotFather |
| `ADMIN_ID` | Необязательный числовой Telegram ID для уведомлений об ошибках |
| `DATABASE_PATH` | По умолчанию на Render: `/tmp/bot.sqlite3` |
| `WEBHOOK_SECRET` | Необязательный секрет для проверки Telegram webhook; если не задан, генерируется при старте |
| `WEBHOOK_BASE_URL` | Необязательный URL сервиса; на Render автоматически используется `RENDER_EXTERNAL_URL` |
| `TRANSFER_FEE_TEXT` | Информационное сообщение о комиссии |

## Локальный запуск

Для локального webhook-тестирования задайте `WEBHOOK_BASE_URL` публичного HTTPS-туннеля, например через свой tunnel-провайдер. Для обычного локального запуска без публичного адреса webhook не зарегистрируется.

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
# Заполните BOT_TOKEN и WEBHOOK_BASE_URL
python main.py
```

## Проверка после деплоя

1. Откройте публичный адрес Render + `/healthz`; ожидаемый ответ — `ok`.
2. Владелец отправляет боту `/start`.
3. Подключает бота к Telegram Business и выдаёт доступ к нужным чатам и право отвечать.
4. Другой пользователь пишет бизнес-аккаунту.
5. Владелец открывает `/contacts` в личном чате с ботом и убеждается, что контакт появился.
6. Владелец отправляет `.off @username https://t.me/nft/PlushPepe-123 1400 star`.
7. Проверяет, что предложение пришло от Business-аккаунта.
8. Получатель нажимает «Принять» или «Отклонить». Проверить, что исходное сообщение отредактировалось и кнопки исчезли.

Если отправка не проходит, смотрите логи Render и проверьте Business Connection, право `can_reply` и время последнего входящего сообщения.
